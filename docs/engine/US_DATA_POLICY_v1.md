# 미국 개별주 데이터 원칙 v1 (EINT-036)

작성 2026-10-12, Claude Code. 미국 데이터 경로 2단계(개별주 일봉)의 규칙을 **수집 전에** 고정한다.
이 문서는 전략 가설이 아니다. 어떤 수익률·신호도 계산하지 않으며, 전략 후보는 3단계에서 별도
사전등록한다. 이 문서를 바꾸려면 v2를 새로 만들고, 코드의 고정 해시도 함께 바꾼다.

## 1. 확인된 사실 (2026-10-12 운영 서버에서 조회)

| 항목 | 결과 |
|---|---|
| Alpaca 일봉(SIP) 시작 | 2016-01-04 |
| 상장폐지 종목 일봉 | 남아 있음: SIVB 2023-03-09, TWTR 2022-10-27, ATVI 2023-10-13 마지막 거래일까지 |
| 분할 조정 | `adjustment=split`이 정상(AAPL 2020-08-31 4:1) |
| 티커 변경 | 과거 전체가 **새 티커**로 조회됨(META는 2021년부터 존재). 옛 티커(FB)도 변경 전날까지 따로 조회됨 |
| 합병 신설 | 별개 종목으로 존재(DISCA 2022-04-08 종료, WBD 2022-04-11 시작) |
| 구성 종목 원천 | 위키백과 "List of S&P 500 companies"의 현재 구성표(`id=constituents`)와 "Historical components of the S&P 500"의 변경표(`id=changes`), 두 문서 모두 판 번호(revid) 조회 가능 |
| 기업행위 | Alpaca `v1/corporate-actions` 조회 가능(분할, 티커 변경 등) |

## 2. 유니버스

- v1은 **S&P 500 시점별 구성 종목**만 쓴다. 나스닥100은 대부분 S&P 500과 겹치고, 위키백과 변경 이력이 덜 정형화되어 있어 v1에서 제외한다.
- 기간은 Alpaca 일봉이 있는 **2016-01-04 이후**만 쓴다.
- 구성 이력은 현재 구성표에서 출발해 변경표를 날짜 역순으로 되돌려 만든다. 편입일 당일부터 구성 종목, 편출일 당일부터 비구성 종목으로 본다. 결과는 종목별 `[시작, 종료)` 구간으로 저장한다.
- 수집할 때마다 두 위키백과 문서의 판 번호와 추출한 표의 SHA-256을 함께 저장한다. 두 판이 모두 같으면 다시 만들지 않는다.

## 3. 생존 편향과 그 한계

- 편출·상장폐지 종목을 **포함**한다. 구성 기간 동안의 일봉을 받고, 마지막 거래일을 기록한다.
- 위키백과 변경표는 공식 S&P 자료가 아니다. 빠진 변경이 있을 수 있다. 그래서 2016년 이후 매월 말 구성 종목 수를 계산해 **495~510 범위를 벗어난 달은 `membership_review`로 표시**한다. 연구 단계에서 그 달을 쓸지는 사전등록에서 정한다.
- 월말 구성 종목 중 그날 일봉이 있는 비율(coverage)을 매번 기록한다. 99% 미만인 달은 검토 대상으로 표시한다.
- 상장폐지의 마지막 가격은 마지막 거래일 종가로만 저장한다. 파산·거래정지 후 폐지처럼 실제로 팔 수 없었던 경우의 손실 반영(예: 폐지 수익률 할인)은 **데이터 단계가 아니라 3단계 사전등록에서 정한다**. 데이터에는 "마지막 일봉 날짜"와 "구성 종료일"을 모두 남겨 이 판단이 가능하게 한다.
- 이 한계는 화면이나 보고서에서 숨기지 않는다.

## 4. 티커 변경과 별칭

- 구성 이력의 티커는 Alpaca의 **현재 티커**로 바꿔 저장한다. 근거는 Alpaca 기업행위의 티커 변경 기록과 수동 별칭 표다. 수동 별칭은 근거(출처와 날짜)를 함께 적는다.
- 옛 티커와 새 티커가 같은 회사로 판정되면 일봉은 **새 티커 하나만** 쓴다. 옛 티커 일봉을 따로 더해 같은 회사가 두 번 들어가지 않게 한다.
- 합병으로 새 회사가 생기면 별개 종목으로 본다(기존 종목은 폐지, 새 종목은 편입 기록을 따른다).
- 별칭으로 연결되지 않아 구성 기간 중 일봉이 비는 종목은 `history_gap`으로 기록하고 메우지 않는다.

## 5. 가격 저장 (1단계 ETF 경로와 같은 원칙)

- 원시(무조정) 일봉은 처음 받은 값을 고정한다. 이후 공급자 값이 달라지면 덮어쓰지 않고 실행 기록의 `raw_revisions`로 남긴다.
- 분할 조정과 분할·배당 조정은 공급자가 과거를 다시 계산하므로 일자별 **조정 계수**(조정 종가 ÷ 원시 종가)만 저장하고 실행마다 해시를 남긴다.
- 마감 후 20분이 지난 NYSE 정규장 세션만 저장한다.
- 저장 단위는 `종목·연도` 문서 하나(약 700종목 × 11년). 서버 메모리와 백업 용량을 고려한 선택이다.
- 1단계 ETF와 같은 원천을 쓴다(Alpaca SIP, Yahoo 교차검증). 교차검증은 매 실행마다 무작위 아닌 **고정 규칙**으로 고른 표본 20종목에 한다(티커 사전순 SHA-256 상위 20개).

## 6. 하지 않는 것

- 수익률, 신호, 순위, 추천을 계산하지 않는다. 한국 엔진·추천·원장·레버리지 DCA와 연결하지 않는다.
- 미래 구성 정보로 과거를 고르지 않는다. 데이터는 구성 구간과 함께 저장하고, 연구는 각 날짜의 구성 종목만 써야 한다(3단계 사전등록의 필수 조건).
- 위키백과 원문을 화면에 재게시하지 않는다(표에서 날짜·티커만 추출).

## 7. 완료 기준 (2단계)

1. 2016-01-04 이후 S&P 500 구성 이력과 월별 구성 종목 수·coverage 보고.
2. 구성 이력에 나온 모든 종목의 구성 기간 일봉 백필(편출·폐지 포함).
3. 매 거래일 자동 증분 수집과 실행 기록(출처, 판 번호, 해시, 교차검증, 검토 표시).
4. 위 결과를 운영 상태 API로 확인할 수 있을 것. 연구용 내보내기(SQLite 스냅샷 + 해시)는 3단계에서 붙인다.
