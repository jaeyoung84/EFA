# 실브로커 어댑터 도입 전 보안 설계

현재 배포본은 모의 주문과 프로세스 내부 로컬 샌드박스만 지원한다. 이 문서는
**실브로커 연결 구현이 아니며**, 어떤 환경 변수나 API도 실거래 주문을 만들지 않는다.

## 필수 어댑터 계약

실브로커별 구현은 다음 기능을 별도 보안 검토와 테스트를 거쳐 제공해야 한다.

1. `client_order_id` 기반 멱등 주문 제출과 재시도 시 같은 결과 조회
2. 주문 조회, 취소, 정정, 부분 체결 및 최종 체결 상태 전이
3. 거래시간·휴장·종목 거래정지·호가 단위·수량 단위 검증
4. 주문 전 위험 한도와 주문 후 계좌/포지션 대사
5. 네트워크 시간초과·중복 응답·브로커 장애 시 안전한 `unknown` 상태 처리

## 보안 경계

- 자격증명은 Secret Manager 또는 배포 플랫폼 런타임 주입만 사용한다.
- API·화면·감사 로그에는 키, 토큰, 계좌번호 원문을 남기지 않는다.
- 실거래 어댑터는 모의체결 경로와 별도 네트워크 정책·배포 환경으로 분리한다.
- 전역 킬스위치, 사용자 권한, 브로커별 킬스위치가 모두 닫힘 상태를 기본값으로 한다.
- 주문·상태·감사 로그는 외부 append-only/WORM 보관소로 복제 가능해야 한다.

## 승인 관문

1. 로컬 계약 검증 및 증권사 공식 샌드박스 검증을 분리한다.
2. 서로 다른 운영자 2인의 준비 검토는 권한 부여가 아닌 검토 기록으로만 유지한다.
3. 장애·중복·부분체결·취소·복구 훈련을 독립 테스트한다.
4. 실제 주문 권한은 별도 배포·별도 코드 검토·명시적 사용자 승인을 거쳐서만 논의한다.

## 금지 사항

- 이 문서를 근거로 `LIVE_TRADING_ENABLED`를 켜거나 킬스위치를 해제하지 않는다.
- 로컬 샌드박스 통과 결과를 실브로커 연결 승인으로 해석하지 않는다.
- 개인 개발 DB 또는 `.env.desktop`에 실계좌 자격증명을 저장하지 않는다.
